# 生产审查复核与修复计划

> 执行方式：使用 executing-plans（计划执行）技能逐项实施；按用户要求在本任务内独立连续完成，不调用子代理，不暂停等待阶段确认。

**Goal（目标）：** 对原报告的 13 项后端与部署问题分别验证触发条件，修复真实缺陷，并纠正超出证据范围的结论。

**Architecture（架构）：** 沿用现有数据库事务、发布与任务流程。在字段解析、请求读取、分析依赖及运维服务各自边界修复；以失败场景回归证明修复有效。保留原始审计与版本数据，不操作生产环境。

**Tech Stack（技术栈）：** Python（后端语言）、FastAPI（接口框架）、SQLAlchemy（数据库访问）、pytest（测试工具）、PostgreSQL（生产数据库）、Docker（容器工具）。

## 基线与约束

- 起点提交为 bd6c6e3（修复前版本）；工作区原本干净，原报告为被忽略的本地文档。
- 后端及盘点工具基线 340 项测试通过；类型检查有 3 项多余类型转换诊断。
- 初始解释器为 3.13.5（本机版本），生产要求 3.12（生产版本）；后续已建立 Python 3.12.14（运行时）验证环境。
- 用户明确接受源码测试与静态核查，不要求启动容器；部署配置问题与实际镜像验证分开记录。
- 不审查或修改前端，不删除用户文件，不提交秘密信息，不发布或部署。

## 任务 1：逐项复核并修订报告

读取报告指向的实现、调用链、现有测试及运行配置。对每项补充可独立运行的回归，先确认修复前失败，再修改实现。镜像兼容性按实际构建配置和工具版本验证；不能把可能影响直接写成生产事故。

## 任务 2：原始财务字段与一致性校验（原第 5、6 项）

修改 backend/app/parser/valuation_parser.py（估值表解析器）、backend/app/parser/interface.py（解析结果结构），必要时调整原始字段来源记录。测试放在 backend/tests/parser/test_valuation_workbook.py（解析测试）与现有校验测试中。

1. 构造同时有数量、单位成本、总成本、市价、市值及占比的工作簿；验证成本 100 不被读作 10，市价 99 不被反算覆盖。
2. 运行新增测试，记录失败。
3. 采用明确表头匹配，原始字段直接解析，缺失价格保持缺失；使数量乘价格校验保留独立输入。
4. 覆盖列重排、标签别名、缺失和零数量，再运行解析、校验与导入测试。

## 任务 3：备份、保留期与邮件（原第 1、2、4、12、13 项）

修改 backend/app/system/backup.py（备份服务）、retention.py（保留期服务）、maintenance.py（维护服务）、settings.py（配置服务）、backend/app/mail/client.py（邮件客户端）、backend/Dockerfile（镜像构建文件）。测试放在 backend/tests/system（系统测试）、backend/tests/mail/test_client.py（邮件测试）、backend/tests/test_maintenance.py（维护测试）。

1. 用隔离目录和文件删除替身验证备份失败、超时、空文件、归档损坏均不会轮转；成功归档可按范围清理并保留最新恢复点。
2. 明确使用兼容生产数据库 16 的备份与恢复客户端，校验非空归档及全部数据段可读。
3. 邮件连接显式创建验证证书及主机名的上下文，证书失败不得进入登录。
4. 保留期读取与配置展示共用有效配置，预演和执行采用同一值。
5. 邮件配置缺失、连接失败和普通异常均返回受控结果及不含秘密的审计。
6. 每项先失败复现，再实施最小修复并运行对应测试。

## 任务 4：上传与查询边界（原第 3、10 项）

修改 backend/app/api/imports.py（上传接口）、backend/app/main.py（应用入口，若需要）、deploy/Caddyfile（代理配置）、backend/app/api/dashboard.py（看板查询）。测试放在 backend/tests/imports/test_api.py（上传测试）、backend/tests/api/test_dashboard.py（查询测试），必要时增加专门的流式请求边界测试。

1. 用请求流计数证明未认证请求不解析文件；已认证超限、分块和多文件请求受实际字节上限约束。
2. 认证先于手动多段解析；应用计数与代理硬上限同时覆盖上传入口。
3. 查询先补齐有效起止日期，再检查倒置与五年上限；保留有界历史查询能力。
4. 运行权限、上传、看板与导出回归。

## 任务 5：历史分析、回撤与公司成分（原第 7、8、9、11 项）

修改 backend/app/imports/processor.py（导入流程）、backend/app/analytics/service.py（分析服务）、company.py（公司指数）、drawdown.py（回撤计算，若需要）、backend/app/api/catalog_funds.py（产品启停）、backend/app/api/dashboard.py（状态展示）及必要的任务排队服务。

1. 中间缺日补录与历史修订后，验证后续产品收益和公司指数重算，等待期间不能报为就绪。
2. 最大回撤只使用截至当日的累计值；后续大跌不能改变较早风险判断，恢复日保留历史最大回撤。
3. 零资产或正负资产相抵时在除法前返回不可计算值，并验证后续分析可结束。
4. 产品启停触发公司历史重算；待处理、全部停用和重新启用时不得读取旧成分结果。
5. 先运行新增失败测试，再修复并运行分析、发布、导入和目录接口回归。

## 任务 6：整体检查与交付

1. 复核基线中 3 项类型检查诊断及其依赖环境，修复确认的问题，不扩大业务变更。
2. 执行 python -m pytest backend/tests tools/valuation_inventory/tests -q（后端与工具完整测试）、ruff check backend tools/valuation_inventory（规范检查）、ruff format --check backend tools/valuation_inventory（格式检查）、ty check backend/app（类型检查）。
3. 审阅完整差异，检查认证、事务、资源上限与错误分支，无前端改动及秘密文件。
4. 在原报告追加逐项复核与修复结果，记录真实验证环境、剩余生产验收边界及既有数据需重处理的范围。
